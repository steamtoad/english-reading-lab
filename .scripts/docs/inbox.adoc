= Inbox Layer: raw capture и processed staging
:revdate: 2026-08-25
:toc:

== Назначение

Inbox Layer принимает быстрые сырые записи до их анализа и преобразования в постоянные UUID-документы Zettelkasten.

Текущая реализация поддерживает только staging workflow:

`capture → inbox/raw → ручная обработка → inbox/processed`.

Она не импортирует элемент в Note или Memo, не добавляет его в `all-todays` и не делает processed источником истины.

== zt-inbox.zsh

Создаёт новый файл в `inbox/raw/`:

[source,bash]
----
.scripts/zt-inbox.zsh "Название входящего элемента"
----

Формат:

[source,asciidoc]
----
= Название входящего элемента
:captured-at: 2026-08-25T23:12:10+0500
:source: manual

----

Свойства:

* заголовок обязателен, не может быть пустым или многострочным;
* timestamp используется как базовое имя файла;
* коллизии получают последовательный числовой suffix;
* exclusive create через `zsh/system` не позволяет перезаписать существующий файл при гонке;
* путь созданного файла выводится в stdout;
* файл открывается командой `$EDITOR`, включая аргументы редактора.

== zt-processed.zsh

Переводит непосредственный файл `inbox/raw/` в `inbox/processed/`:

[source,bash]
----
.scripts/zt-processed.zsh 2026-08-25-231210.adoc
.scripts/zt-processed.zsh /path/to/zettelkasten/inbox/raw/2026-08-25-231210.adoc
----

Свойства:

* basename разрешается относительно `inbox/raw`;
* полный путь после canonical resolution обязан указывать на непосредственный файл `inbox/raw`;
* вложенные пути, внешние файлы и symlink-выходы отклоняются;
* существующий destination не перезаписывается;
* destination резервируется hard link до удаления raw-файла;
* после успеха путь processed-файла выводится в stdout.

`inbox/raw` и `inbox/processed` должны находиться на одной файловой системе.

== Конфигурация

Корень Zettelkasten выбирается в порядке:

. `ZK_HOME`;
. `ZETTELKASTEN_ROOT` как совместимый fallback;
. родитель каталога `.scripts`.

== Ошибки и восстановление

Оба скрипта завершаются ненулевым кодом и пишут сообщение в stderr при неверных аргументах, невозможности создать каталоги, коллизии назначения, выходе пути за разрешённые границы или ошибке файловой операции.

Если удаление raw-файла после создания hard link не удалось, `zt-processed.zsh` удаляет созданный destination и сообщает об ошибке, сохраняя исходный raw-файл.

== Проверки

Минимальная проверка изменения Inbox Layer:

. `zsh -n` обоих скриптов;
. capture во временном `ZK_HOME`;
. проверка AsciiDoc document attributes;
. обработка по basename и полному пути;
. отказ при пустом/многострочном заголовке;
. отказ для внешнего, вложенного и symlink-пути;
. отказ при существующем destination без изменения обоих файлов;
. `zt-check` рабочего Zettelkasten;
. `git diff --check` изменённых файлов.
